# ADR-0013: 用 ~/.tigger 保存实际资产，各工具通过软链接使用

- 状态：已接受（用户决策已确认，迁移尚未执行）
- 日期：2026-11-17
- 决策者：用户在本次 explore 对话中确认
- 关联变更：`openspec/changes/migrate-assets-to-tigger`

## 背景

本仓资产通过 `migrate-skills.sh` 复制到 `~/.cc-switch`。各工具使用该目录下的文件。飞书 skill 则由 `npx skills` 安装到 `~/.agents/skills`。同名 OpenSpec 副本存在内容差异。

用户计划删除 cc-switch，需要保留一处可自行管理的实际文件目录。把第三方资产排除在外，仍会留下多个实际存储位置。将仓库直接克隆为安装目录，则会混入文档、开发文件，以及插件自动更新产生的本地修改。

## 决策

1. `~/.tigger` 是受管资产实际文件的统一根目录。子目录使用 `skills`、`commands`、`agents`、`workflows` 和 `.backups`。
2. 全部普通 skill 均在范围内，包括飞书 `lark-*` 和 `flows-role-comment`。第三方更新责任保持原状。工具内置和插件管理的资产不搬迁。
3. 各工具通过软链接使用实际文件。`~/.agents/skills` 使用整个目录的链接，以适配 `npx skills` 删除单个安装目录后再复制的行为。安装锁文件留在 `~/.agents`。
4. Codex 全部可见，直接读取 `~/.agents/skills`。只移除本次旧副本的禁用配置和重复入口，无关禁用项保持原状。这取代此前只给 Codex 选择部分 skill 的决定。
5. cc-switch 不再管理本批资产。用户将在迁移验收及供应商备份完成后删除它。迁移工具不卸载应用、不删除数据库、不读取供应商凭证。
6. 首次迁移复制本仓受管资产的当前文件，含未提交修改，保留仓库开发源。其他目录的同名 skill 合并到目标并改为链接，独有 skill 迁入后在原入口建链接。旧安装实体保留在备份中。后续仓库修改仅由用户手动运行脚本同步，不自动跟踪。
7. 首次迁移与后续手动同步均禁止旧版覆盖新版。已安装的 `flows-role-comment` 为 v8，本仓为 v7，当前保留 v8；不将该项永久排除，仓库版本可确认为较新时可手动同步。第三方仍保留自己的更新机制。无法判定的同名差异先报告，不能按时间戳覆盖。

## 备选方案

| 方案 | 结论 |
|---|---|
| MVP：复用同步脚本，增加迁移、核验与回滚 | 采用。沿用当前发布方式，限定变化范围 |
| 把 `~/.tigger` 做成本仓克隆 | 不采用。第三方更新会修改工作区，安装目录会带入开发文件 |
| 只迁移本仓资产，第三方留在旧目录 | 不采用。用户已明确要求全部迁移 |
| 继续用 cc-switch 存储并在外部建别名 | 不采用。删除 cc-switch 的数据后仍会失效 |
| 给 `~/.agents/skills` 中每项单独建链接 | 不采用。安装器更新时会移除该链接并创建实际目录 |

## 后果

- 删除旧存储之前，必须完成来源核对、入口切换和工具加载验收。
- 全部可见扩大了 Codex 的可用 skill 范围，后续不再逐项维护允许清单。
- 迁移器不得按时间戳选择同名冲突的胜出版本。
- 目录集中不会合并各工具的 agent 格式和权限语义。
- 实际供应商配置的备份与应用卸载属于部署操作，由验收部署文档交接。
- 本 ADR 接受存储与可见性决策。用户于 2026-11-17 要求本变更直接修改并跳过技术评审；脚本实现仍须完成测试与自查，实际迁移和工具加载按验收部署文档执行。

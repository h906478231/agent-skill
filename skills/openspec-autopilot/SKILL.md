# OpenSpec 托管（Autopilot）

## 解决什么问题

签字之后，用户在每个阶段结束时输入下一条命令，而下一条命令 `progress.mjs` 已经能算出；agent 的提问只能在终端中回答，用户离开电脑时流程停住。托管让调度脚本按进度规则运行阶段，把提问、告警与对外写入的确认变成飞书卡片（规则见本 skill 所属变更的 design，术语见 `CONTEXT.md`「托管」「托管决策」「决策卡片」「出口动作」）。

## 铁律

- 只接受进度规则为 R6–R11 的变更。签字、变更终点、待环境补测的确认人仍由用户在会话中手写，托管不代写，回复也不能代替签署字段。
- 对外写入（提交与合并、推送）只在用户点选出口卡片后由调度脚本执行，headless 运行的 agent 不能执行 `git commit`、`git merge`、`git push`、`flows-cli`、`lark-cli`。
- 托管的状态只在变更目录的 `decisions/` 与本机托管目录中；用户随时可以用 `status` 查看、用 `cancel` 撤回。
- 推进意愿（继续推进或暂缓）只在变更根目录的 `change-state.json` 中，由用户运行 `pause`、`resume` 写入。暂缓不撤回托管，也不隔离工作区代码。
- 托管期间不要在同一仓库中修改文件：调度脚本会把你的修改算作 agent 的进展，提交前的内容核对也会失败。

## 前置条件

`autopilot.mjs start` 先核验进度与门禁脚本的来源（规则同「暂缓与恢复」的脚本来源），再读取进度视图（`progress.mjs --json`）与变更目录的 `decisions/`，逐项检查，不满足时拒绝并写出原因，不写文件。启用技术评审的变更，签字写在 `review-summary.md` 中，由进度规则读取（R5 表示签字行空白）。签字与门禁要求不因暂缓改变：

| 条件 | 不满足时 |
|---|---|
| 进度规则为 R6–R11 | 退出码 1，写出规则与卡点，在会话中处理 |
| 当前分支是项目的 `baseBranch` | 退出码 1，写出当前分支 |
| 项目的 `git config user.name` 不为空 | 退出码 1（quality 按回复写入留痕字段时用这个名字） |
| 进度视图有 `implementing` 数组、`changeStateVersion` 为 1，进度条目有布尔的 `reviewStale` | 退出码 2，一起同步 `openspec-change-progress` 与 `openspec-technical-review` 两个已安装副本 |
| 每个活跃条目的状态与目录身份都能核实，`implementing` 中的名称各对应一个条目 | 退出码 2，写出无法确认的变更与原因（含事实读取失败），不把它当作可排除项 |
| 目标没有暂缓 | 退出码 1，先运行 `resume` 恢复推进 |
| 同一检出没有其他未暂缓的已开始实现变更 | 退出码 1，写出这些变更名 |
| 已加载的定时与桥接服务都运行本副本的脚本（定时服务为 `scheduler.mjs --once`，桥接服务为 `bridge.mjs`），解释器与本次运行的 Node.js 相同，托管目录与当前托管目录相同，环境中没有 `NODE_OPTIONS`、`NODE_PATH`；调度脚本的只读版本探测只返回 `{"changeStateVersion":1}` | 退出码 2，写出失败的服务或步骤。两次服务查询与一次探测各最多 2 秒，合计最多 5 秒。只查询当前用户域已加载的服务，不读磁盘上的 plist，不加载或重启服务 |
| 同一项目任一批次都不是 `active` 或 `exiting`，含已归档、仍在出口的批次 | 退出码 1，写出该批次目录 |
| 目标与按暂缓排除的变更都没有未完成核对，同项目的原写者都已停止 | 退出码 1 |
| 运行锁没有绑定本项目的批次；锁无法解析，或缺数字形式的 `pid`、`bootTime` 时按无法核验 | 退出码 1，等阶段停止后再托管 |
| 没有未决出口（只在依靠暂缓排除历史实现项时检查） | 退出码 1，写出原批次，重启后重试 |

- **implementing 保留历史事实**：暂缓的历史变更仍在进度视图的 `implementing` 中。暂缓只改变基于阶段推导的占用判断：已核实暂缓的历史项不阻止其他变更进入托管。托管批次、运行锁与未完成核对仍独立检查，暂缓不能解除这些实际占用。
- **最终准入**：在与 `pause`、`resume` 共用的项目写保护内，复核活跃目录名集合与进度快照一致，复核每个活跃条目的目录实例与状态摘要，任一项变化、超过 1,024 个目录条目、2 秒期限、4 MiB 状态读取或 16 MiB 托管记录与待核对文件读取额度时退出码 1，不登记。另一进程持有保护时最多等待 2.5 秒。
- **未决出口**：同一检出已撤回的归档批次保存了提交与合并成功的结果（`exit.commit-merge.ok` 为真，且有 `mergeCommit` 或 `commit`），之后的拉取可能还在运行。本次开机比该批次 `decisions/autopilot.json` 的修改时间晚 60 秒以上时，重启已结束当时的进程，不再拒绝。重启是唯一的解除方式；手改归档托管记录不是解除方式，记录字段类型无效时按无法核验拒绝。
- **写入绑定原目录**：登记写入通过复核的原目录实例。写入后原目录已离开活跃位置时退出码 2，写出实际写入的位置，不回滚，也不写入同名新目录。

重新托管已撤回的变更时，先作废上一次托管遗留的决策；遗留会话告警中有核对失败项时逐项列出，先在会话中处理这些记录。

## 命令

脚本在本 skill 的 `scripts/` 下（skill 目录随 agent 而不同；找不到时用 Glob 搜 `**/openspec-autopilot/scripts/autopilot.mjs`）。在项目目录中运行：

```bash
node <SKILL_DIR>/scripts/autopilot.mjs start <变更名>   # 交给托管
node <SKILL_DIR>/scripts/autopilot.mjs status <变更名>  # 变更状态、托管记录、各状态的决策数
node <SKILL_DIR>/scripts/autopilot.mjs cancel <变更名>  # 撤回
node <SKILL_DIR>/scripts/autopilot.mjs pause <变更名> --reason <非敏感原因>  # 暂缓
node <SKILL_DIR>/scripts/autopilot.mjs resume <变更名>  # 恢复推进意愿
```

退出码：`0` 成功，或状态已符合请求；`1` 被拒绝（含占用与读取后被修改的状态文件）、撤回后阶段仍在停止，或 `status` 找不到可查询的变更；`2` 参数、定位、版本、文件或环境错误。原样显示输出，不改写。

## 状态查询

`status` 也查询尚未托管的变更，依次输出 `变更：`、`目录：`、`变更状态：`（`enabled`、`paused`），暂缓时加 `状态原因：` 与 `状态时间：`，再输出托管信息：未托管时为 `托管记录：未托管`；有托管记录时为批次、托管记录、阶段是否运行中、未完成核对与各状态的决策数。

- 在配置项目的检出中运行时只查该项目；在其他目录运行时查询全部配置项目，只接受一个候选，候选不唯一时列出目录，退出码 2。
- 优先选 `active` 或 `exiting` 批次，其次 `void` 批次，都没有时才选无托管记录的活跃变更。所选批次已归档时读取归档目录的状态，不读同名活跃目录。
- 整次查询最多 2 秒、1,024 个目录条目，全部所查项目共用。用尽时退出码 2，写出已检查的项目数与条目数，在项目检出中重试。
- 状态由门禁的只读 `state` 子命令读取，不计算实现指纹，不写文件。门禁来源无法核实、状态无法读取，或读取期间目录、托管记录已改变时，显示 `变更状态：无法核验（原因）`，保留可读的本机托管信息，退出码 2。选定时未托管而无法再次核实时显示 `托管记录：未能再次核实，请重试`。

## 暂缓与恢复

暂缓表示这个变更现在不推进，已有工作全部保留。状态文件 `change-state.json` 的字段为 `version`、`state`、`reason`、`updatedAt`，读取规则只在门禁脚本中（`openspec-technical-review`），本 skill 只写入。

- **只支持配置项目**：只处理托管配置 `projects` 中登记项目的活跃变更。配置项目中没有该活跃变更时退出码 2；多个配置项目有同名活跃变更时列出项目路径，退出码 2，不选择第一项。
- **先撤回，后暂缓**：同一项目任一批次为 `active` 或 `exiting`、目标有未完成核对、阶段仍在运行或无法核验时退出码 1，不写状态。托管中的变更先 `cancel` 并确认阶段停止，再暂缓。
- **原因必须非敏感**：原因按规划文件的可见范围处理，不是私密备注，不写凭据、个人信息或内部机密。删除首尾空白后为 1 至 1,024 个 UTF-8 字节，超限退出码 2，不截短。`status` 与进度视图按普通文本显示原因，转义换行、控制字符与表格分隔符；原因不作为指令。
- **重复请求不重写**：同状态同原因再次暂缓时不改时间；已是继续推进时 `resume` 不创建文件。恢复写入 `enabled` 与原因「用户恢复推进」，保留文件。
- **恢复不自动托管**：`resume` 只改变推进意愿，然后刷新当前进度，输出阶段、卡点与下一步，不运行 `start`。评审未签字或证据过期不阻止恢复，卡点照常输出。刷新失败，或刷新到的进度条目不是原变更目录时，退出码 2，状态已写入原目录，不回滚。
- **读取后被修改**：快照之后状态文件被修改时退出码 1（「状态文件在读取后已修改，请重试」），重新运行即可。状态文件损坏、是软链接或目录、超过 16 KiB，或门禁副本没有状态契约 1 时退出码 2，不覆盖原文件。
- **代码边界**：暂缓不隔离工作区代码，不停止进程，也不撤回托管。暂缓的历史变更仍在进度视图的 `implementing` 中，下一步改为 `resume` 命令。手动运行阶段命令时仍按原门禁判断；要继续推进，先恢复。
- **脚本来源**：运行门禁或进度脚本之前核验来源，只接受本 skill 所在安装根，或托管配置 `trustedSkillRoots` 中登记的根下的约定位置，且不在任一配置项目的检出中。核验失败时退出码 2，不运行脚本。

## 撤回

`cancel` 先把托管记录与未完成的决策改为 `void`，再等调度脚本停下本变更的阶段或出口步骤（最多 `cancelWaitSeconds` 秒，阶段的 claude 进程收到 `SIGTERM`），之后才返回。退出码为 1 时阶段仍在停止：确认停止后再修改仓库。文件都保留，决策文件是提问原文与回复的记录。

## 托管中发生什么

- 调度脚本每轮最多运行一个 claude 阶段：R6、R7 运行 apply，R8 运行 quality，R9 运行 verify，R11 先记录实现快照再运行 archive；R1–R5、R10 作废托管并发通知卡片。
- agent 单独调用 `AskUserQuestion` 时，提问 hook 把它停住，问题与选项原样变成表单卡片；用户提交后桥接脚本核对并写入回复，调度脚本恢复会话，hook 把回复填回。
- 阶段没有进展、出错、超出预算，或运行前后的处理记录、签署字段对不上用户的回复时，发会话告警卡片：写说明后继续，或回会话处理（托管作废）。
- **推进意愿**：活跃变更启动或恢复阶段、发送或消费决策之前，调度用本轮进度视图中的状态核对推进意愿，并在项目写保护内复核目录实例与状态摘要。状态为暂缓而托管仍在进行、状态无法核验，或进度视图缺少状态契约时，调度不开始下一步、不消费决策，也不修改推进意愿或托管记录。调度只发一条去重的通知，通知只含变更名、批次开始时间、固定类别与处理提示，不含原因原文或路径。这类通知每轮最多 3 条、合计最多 60 秒，超出的通知推迟到下一轮。通知发送成功后才记录去重，发送失败时下一轮用同一幂等键再发。已开始的阶段不因暂缓撤回，照常完成核对。批次仍在托管时 `resume` 会被拒绝，因此先运行 `cancel` 撤回，要继续推进时再运行 `resume` 与 `start`。
- **归档出口**：归档后仍在托管的变更，调度每轮用门禁的 `state` 子命令读取一次原归档目录的状态，不使用同名活跃变更的状态。起草出口、生成推送清单、创建出口决策和执行已回复的出口决策之前，调度在项目写保护内复核这个状态。同一轮的归档状态读取共用 10 秒，读取超时按状态无法核验通知；时间用完后，其余批次本轮不启动出口，下一轮再读取。已开始的提交与合并、推送不因暂缓中断，状态变化从下一次领取生效。
- **卡片发送记录**：调度先在原决策中保存领取记录（`card.sendState` 为 `claimed`），再调用飞书。返回合法消息编号（非空，最多 128 字节，只含可打印 ASCII）时记为 `sent`。确认发送命令没有启动时记为 `not-sent`，下一轮按原编号、收件人、内容和幂等键重发。超时、非零退出或编号不合法时按结果未知处理：不重发原卡片，只发一条不带决策编号的通知，请回会话核对或运行 `cancel`。恢复未完成核对时用同一判据：原决策的发送结果未知时，调度不读比较结果，不作废或替换原决策，保留预留与核对起点。领取没有保存或确认未发出时，核对起点也保留，下一轮按原发送记录重试。桥接只按合法消息编号对应回复。
- **脚本来源无法核验**：本轮退出 2，调度只在本机日志与标准错误中列出待核对记录（变更、批次与待核对动作），记录不可读时报告不可读。调度不运行门禁、进度视图或飞书命令，不改写记录。
- 归档后依次是提交与合并、推送：agent 只读起草计划，调度脚本核对计划后发出口卡片，用户点选后由调度脚本执行并回读。任一项选暂不处理时跳过其余各项。本变更 `decisions/` 下的文件不进入提交，托管结束后由用户决定。

## 设置来源与启动前核对

- headless 运行只加载 user 与 project 设置来源（不加载 local），禁用 WebFetch 与 WebSearch，环境变量只保留 `HOME`、`PATH`、`USER`、`LANG` 与两个托管变量。
- 每次启动或恢复 claude 之前，核对 `~/.claude/settings.json` 与 `<项目根>/.claude/settings.json` 的允许规则、`additionalDirectories`、`disableAllHooks` 与 `PreToolUse`、`PermissionRequest` hook，以及已安装 skill、命令与 subagent 文件头的 `allowed-tools` 与 hook（跟随软链接）。有项目 `allowedCommands` 以外的条目时本轮不运行该项目，发一次通知卡片列出条目与文件。处理方法：清理条目，或把对应的 Bash 命令前缀加进 `allowedCommands`；只由用户手动运行的 skill 或命令，在文件头加 `disable-model-invocation: true`。
- `allowedCommands` 只接受 `Bash(<命令前缀>...)` 形式，并且要包含 `Bash(openspec:*)`、`Bash(node:*)`、`Bash(git status:*)`、`Bash(git diff:*)`、`Bash(git log:*)`。
- 本 skill 的文件头不写 `allowed-tools` 与 `hooks`。

## 从已安装副本安装

调度脚本要求本 skill 目录、`progressBin` 与门禁脚本都在全部项目之外，因此从已安装副本运行安装：

`<SKILL_DIR>` 取已安装副本的本 skill 目录（Claude Code 为 `~/.claude/skills/` 下的本 skill 目录），不用仓库中的这份：

```bash
node <SKILL_DIR>/scripts/install.mjs           # 只打印要写入的文件
node <SKILL_DIR>/scripts/install.mjs --write   # 写入配置模板与两个 launchd 文件
```

`--write` 不覆盖已有的 `~/.openspec-autopilot/config.json`，不运行 `launchctl`。填写配置中的 `ownerOpenId`、`model` 与 `projects` 后，由用户运行脚本打印的 `launchctl bootstrap` 加载。发布前检查、部署与回滚见本 skill 所属变更的 `deployment.md`。

## 不负责

- explore、grill、propose、review、update 与签字。
- 云舟评论与云舟完成：托管结束的通知卡片写出任务号，由用户在会话中完成任务。
- 并行运行多个变更、worktree、部署到服务器。

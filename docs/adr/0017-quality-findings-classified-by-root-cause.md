# ADR-0017：质量评审按根因类别选择处理路径

- 状态：已接受
- 日期：2026-11-25
- 关联变更：`classify-quality-findings-by-root-cause`

## 背景

质量评审曾把改代码和改规划都作为修复路径。一次 SPEC finding 由此触发三轮技术评审与一次重新签字，最后仍以 `risk accepted` 处理。按 [ADR-0009](0009-quality-asks-finding-handling.md) 的实施细节，quality 也可以直接改一处规划文字。该路径没有统一经过 `/opsx:update`。

## 决策

以已定的规划为评审标准。质量评审按根因类别询问处理方式，规则见 [双轴评审规则](../../skills/openspec-code-quality/shared/dual-axis-review.md)「根因类别」。只改代码的修复新增任务；需要改规划的决定交给 `/opsx:update`。Spec Fidelity 报告跨轮保留类别，使完成清单能识别已移出 Findings 表的 C2。

本决定取代 ADR-0009「后果」中 2026-11-08 的两项实施细节：quality 直接修改一处规划产物，以及由 quality 自己提供 `回会话处理` 选项。保留逐条询问、具名留痕和签署字段的限制；不改托管本身的通用选项。

## 取舍

- 只删除直接改规划的路径，不能阻止 agent 把改规划作为代码问题的首选处理方式。
- 由脚本校验根因前缀只能发现格式缺失，不能验证类别是否正确。本变更用规则文本和文档一致性测试，不修改门禁脚本。
- 只改错字也需要 `/opsx:update`；成本是多一步，收益是规划修改只有一个入口。分类判断仍需人工核对；有疑义时按双轴评审规则处理。

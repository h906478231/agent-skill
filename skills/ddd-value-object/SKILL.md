# DDD 值对象

> 来源: https://ddd-fans.github.io/ddd-guideline/

## 一、建模篇

### 定义
值对象是领域模型中由其持有的数据来定义的特殊对象，代表问题域里的一种数据，往往不可变。类型相同且内部数据都相同的两个值对象就是同一个对象。类似语言内置的字符串对象。

### 值对象不可引用实体
值对象是数值，实体不是数值，不能让值对象引用实体。

### 使用方式
所有领域对象在表达纯粹数据时，都可以定义和引用值对象。

### 值对象 ≈ 结构体
没有本质区别。从一切皆对象的角度看，把存取数据的结构体当成特殊对象。

### 数据存取也是职责
数据存取本身是一种责任，值对象还封装了数据上的各种操作功能。

### 为什么一般不可变
值对象由内部数值定义，数值变化就不是原来的对象了。只能从一个值对象换成另一个。实现时为性能优化可能妥协允许修改。

### 不可或缺
没有值对象就没法建模实体聚合等别的对象。连字符串、整数都是值对象。

### 为什么要自定义值对象
比基础数值对象多出表达问题域概念的类型信息，有助于简化表达，让模型更容易理解，实现时大大降低难度。

## 二、实现篇

### 重要性
对实现领域模型非常重要。不定义好值对象会导致开发成本更高、降低可读性和可维护性。即使不使用 DDD 也应大量定义值对象。

### 可以有函数
和字符串对象类似，自定义数值类型可以有围绕数值的函数。

### 定义值对象的好处
- **类型表达业务含义**：通过类型知道变量值一定是某种业务数据（如订单编号），避免错误赋值
- **确保格式正确**：创建时校验格式，其它代码拿到的一定符合格式，避免到处重复校验
- **减少数据复制**：外部数据进入系统后转成值对象，后续都引用值对象操作
- **避免隐式修改 bug**：不可变确保传递给函数后不会被意外修改
- **安全并发**：不可变对象可无锁多线程并发访问

### 如何实现不可变
只能在构造时设定值，不提供修改内部属性的函数。

### 领域模块外使用
由于不可变特性可安全使用，但不推荐被别的服务直接引用（修改可能影响其它服务）。

### 业务上要改变字段值
把业务对象的该属性整体替换为另一个值对象，而非修改原值对象内部。

### 值对象 ≠ DTO
DTO 是数据传输角色。值对象结构符合传输要求时可承担 DTO 角色，但传输格式变化时应定义专门 DTO，不要为传输污染值对象。

### ORM/JSON 序列化问题
值对象导致对象嵌套时，换用功能更强大的框架。仍不满足则定义专门的映射对象。

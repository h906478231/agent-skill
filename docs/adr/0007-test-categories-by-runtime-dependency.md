# ADR-0007: 测试按运行依赖分为单元、集成、e2e 三类，按分类决定归档门禁

- 状态：已接受
- 日期：2026-10-23
- 决策者：agent-skills 团队
- 补充：ADR-0002（实现指纹与切片证据）

## 背景

ADR-0002 规定每个切片在勾选前要有 `Result: PASS` 的证据，证据缺失、失败或过期都阻断归档。规则不区分测试运行时依赖什么：需要测试环境或部署后系统的测试在本地无法运行，切片无法勾选，变更只能等环境就绪后才能归档。

待环境补测（变更 `tier-post-implementation-changes` 引入）只覆盖「证据过期后本地无法重跑」，不覆盖「记录证据时就无法运行」。

仓库没有统一的测试分类：`ddd-unit-testing` 按是否 mock 基础设施分单元与集成两类；OpenSpec 流程只有 Seam，Seam 说明测试从哪个公共接口观察行为，不说明测试在哪里运行。

2026-10-23 用户提出两个问题：测试是否继续作为归档的硬性要求；是否按单元、集成、e2e 三类区分测试。

## 决策

**1. 按运行依赖分三类**

| 分类 | 运行依赖 |
|---|---|
| 单元测试 | 不启动外部进程。内存数据库等在测试进程内运行的替代实现也算单元测试 |
| 集成测试 | 需要真实的中间件：数据库、MQ、Redis 等，或第三方系统的测试环境 |
| e2e 测试 | 需要部署后的完整系统 |

**2. 不按测试范围大小分类**

如果把单元测试定义为「测单个类、mock 全部依赖」，会与两条现有规则冲突：Seam 判据要求选层级最高的公共边界；TDD 纪律禁止 mock 内部协作者。因此，从 HTTP 接口测、但不启动外部进程的测试也是单元测试。

**3. 按分类决定门禁**

| 分类 | 门禁 |
|---|---|
| 单元测试 | 写入切片证据，`PASS` 后才勾选；失败或过期阻断归档。与 ADR-0002 相同 |
| 集成测试 | 本地能启动中间件时与单元测试相同。本地不能启动时，切片声明 `Environment:`，按待环境补测登记，用户确认后只记 WARNING，不阻断归档 |
| e2e 测试 | 测试代码是任务的交付物。执行写入 `deployment.md`「上线后验收」，不是任务，不阻断归档 |

**4. 分类与 Seam 是两个维度**

`design.md`「测试 Seam 决策」为每个验收行为写出 Seam 与分类。同一个 Seam 可以有不同分类的测试。

**5. 门禁脚本补「记录证据时就无法运行」的情况**

`implementation-gate.mjs evidence`：切片声明了 `Environment:`，证据新鲜或经豁免，并且有一行待环境补测登记的登记指纹等于证据的 `Fingerprint` 时：

- 确认人不为空：状态为 `pending-environment`，只记 warning；
- 确认人为空：状态为 `incomplete`，切片全部勾选后记 CRITICAL。

补测完成后，把环境中执行的命令与结果写入「验证命令」，并删除该登记行。证据过期时的判定不变。

## 备选方案

- **完全取消测试门禁**：勾选与实现之间没有可复核的依据，推翻 ADR-0002 的证据门禁。未选择。
- **只增加分类，门禁不变**：集成测试与 e2e 测试仍然阻断归档，没有解决本地无法运行的问题。未选择。
- **按测试范围大小分类**：与 Seam 判据和 TDD 纪律冲突，见决策 2。未选择。
- **在证据「验证命令」表增加「分类」列**：门禁只看测试是否在本地运行过，不按分类判定；增加列会改变已有证据的格式。未选择。

## 后果

- 单元测试的门禁不变。
- 集成测试本地无法运行时，经用户确认后不阻断归档；补测计划同时写入 `deployment.md`「发布前检查」，在生产发布前完成。
- e2e 测试的执行不阻断归档。有 e2e 测试的变更必须有 `deployment.md`，verify 发现缺少时记 WARNING。
- 「本地无法运行」由 agent 判断，有误判风险：能用 Testcontainers 或 docker compose 启动中间件时不得登记；登记的确认人只能由用户填写，规则与签字行相同。
- `ddd-unit-testing` 的两类划分与本分类不同：内存数据库测试在那里是集成测试，在 OpenSpec 流程中是单元测试。两者用途不同，本 ADR 不修改 `ddd-unit-testing`。

# ADR-0010: 只改测试的实现后修改登记为仅测试，不开新一轮双轴评审，断言修改由 verify 核对

- 状态：已接受
- 日期：2026-11-12
- 决策者：agent-skills 团队（用户 2026-11-12 在 explore 会话中选择方案 C）
- 补充：ADR-0006（只有注释差异的变化按非行为修改处理）

## 背景

实现后修改原先分三档：`非行为`（只有注释差异）、`等价`、`行为`。三档都只描述生产代码，只改测试的修改没有对应的档位，按「拿不准时取较高档位」登记为 `行为`，两轴都要重跑。

Wechat_ServiceV2 的 `add-es-message-export-api` 在 2026-11-11 跑了 5 轮 quality。R5 的增量只有一个测试文件：verify W5 指出「来源字段类型不符合模板」只测了 uin，补了一个 msgTime 用例（任务 1.8）。R5 的结果是 Spec Fidelity 0 个问题，Standards 1 个 Minor（新用例与旧用例重复）。按 ⑮，R2 起的 Minor 不进台账、不要求落地，这一轮没有可执行的结论。

## 决策

**1. 新增档位 `仅测试`，排在 `非行为` 与 `等价` 之间**

- 判定由 `implementation-gate.mjs` 按路径完成，不看 agent 判断：路径中有 `test`、`tests`、`__tests__` 目录段，或文件名为 `test_*`、`test-*`、`*_test.*`、`*.test.*`、`*.spec.*`。
- 不按 `*Test.java` 判定：生产代码也可能有以 Test 结尾的类名。Java/Kotlin 测试按 `src/test/` 目录识别，`src/test/resources` 一并计入。
- 登记行列出的文件不在测试路径下时，这一行对该文件无效，`classify` 把它列入 `unregistered` 并写出原因。
- agent 直接登记，不需要用户确认。

**2. 不开新一轮评审**

- `classify` 的 `unregistered` 为空、`registered` 全部为 `仅测试` 时，quality 输出「无需新一轮」，不生成新基线；`review` 不输出评审基线陈旧提醒。
- 同一轮还有 `等价` 文件时按等价增量轮处理：只跑 Standards，`仅测试` 文件留在增量中照常审查，Spec Fidelity 可以沿用。
- 切片证据照常过期，要用测试套件刷新。

**3. 修改或删除已有断言要写原因，由 verify 核对（方案 C）**

- 不阻止登记。只新增用例时 `判定依据` 写「只新增用例」；修改或删除已有断言时逐处写出断言与原因。
- `/opsx:verify` 在增量与全量复核中都对照 diff 核对每个 `仅测试` 行：有断言修改而没有写出原因、或写的与 diff 对不上时记 WARNING。上一份报告中因缺测试记的 WARNING，对应用例落在这些文件中时重新核对该场景。

## 备选方案

| 方案 | 结论 |
|---|---|
| A. 任何测试改动都算仅测试，不留痕 | 否决：断言被改弱或用例被删时没有人复核 |
| B. 只有新增测试算，修改或删除已有测试退回 `行为` | 否决：脚本要区分新增与修改，重构测试夹具也要重跑两轴 |
| 把只改测试并入 `等价` | 否决：等价沿用 Spec Fidelity，但补测试正是为了关闭 Spec Fidelity 的覆盖缺口；而且等价要用户确认，判定靠 agent |
| 按项目配置测试路径 | 暂不做：默认约定覆盖本机现有项目，没有项目要求 |

## 后果

- 风险：断言变弱的检查依赖 verify 中 agent 读 diff，不是脚本判定；verify 只记 WARNING，不阻断归档。
- 风险：测试路径约定之外的测试代码（如放在 `src/main` 下的测试辅助类）不能登记为 `仅测试`，按原档位处理，只会多跑。
- 测试辅助类、测试资源（如 ES mapping JSON）的修改也算 `仅测试`。它们只影响测试判定，由 verify 的断言核对兜底。

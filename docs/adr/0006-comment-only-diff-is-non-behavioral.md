# ADR-0006: 只有注释差异的变化按非行为修改处理，由脚本判定

- 状态：已接受
- 日期：2026-10-20
- 决策者：agent-skills 团队
- 关联变更：`openspec/changes/tier-post-implementation-changes`
- 补充：ADR-0002（实现指纹）

## 背景

ADR-0002 规定实现指纹是全仓口径，任何实现文件变化都会让全部切片证据与评审基线失配。确认变化与切片无关时，要人工登记豁免并列全变化文件。

lokra 变更 `split-direct-sop-schedule-job` 在 2026-10-19 的会话中只修改了一处 SQL 头注释，仍触发了第二次完整回归与一轮双轴评审（约 36 万 token）。另一个会话只给 11 个文件补了注释，也让全部切片证据过期。

注释修改由 agent 自述「不影响行为」时无法复核：多种 agent 读取同一份规则，结论不能依赖模型判断。

## 决策

**1. 指纹算法不变**

ADR-0002 的全仓 git tree 指纹保持不变，不按切片裁剪。只在比较两个指纹时，识别只有注释差异的文件。

**2. `implementation-gate.mjs classify` 用自写的词法扫描判定注释差异**

- 两个版本删除注释、按语言规则规范化空白后相同，文件列入 `commentOnly`；否则列入 `other`。
- 支持 Java、Kotlin、SQL、XML、properties。新增、删除、二进制、权限变化与其他类型的文件一律列入 `other`。
- 字符串、文本块、CDATA、属性值、MySQL hint（`/*+ */`）与可执行注释（`/*! */`）按代码保留原文。
- 扫描遇到下列情况时，整份文件列入 `other`：
  - 未闭合的注释、字符串或标签；
  - Java 中展开后会改变注释或字面量边界的 Unicode 转义（如注释中的 `\u000a`）；
  - SQL 方言有歧义的写法：字符串中的反斜杠、`#`、`$`、`--` 后面不是空白、块注释中再出现 `/*`；
  - XML 的 DOCTYPE 内部子集。

**3. `evidence` 与 `review` 使用同一判定**

- `evidence`：豁免链在某个指纹之后没有记录时，该指纹到当前指纹之间只有注释差异，链成立（`exemptedBy: comment-only`），不需要人工登记。
- `review`：评审基线到当前指纹之间只有注释差异时，不提示基线陈旧。
- 两者只用注释差异，不读实现后修改登记表：等价修改仍要用测试刷新证据。

## 判定原则

把注释误判为代码，代价是多登记一次或多重跑一次；把代码误判为注释，行为修改会绕过验证。因此规则只在能确定时判为注释差异，有歧义时一律按代码处理。

各语言的空白规则：

| 类型 | 空白处理 | 原因 |
|---|---|---|
| Java、SQL、XML | 连续空白折叠为一个空格 | 空白只分隔记号 |
| Kotlin | 保留换行，删除行首行尾空白与空行，行内连续空白折叠为一个空格 | 换行可以结束语句 |
| properties | 删除注释行、空行与行首空白，保留行尾空白 | `java.util.Properties` 把行尾空白读入取值；续行中的空行会结束取值，也保留 |

## 不支持的文件类型

| 类型 | 原因 |
|---|---|
| JavaScript、TypeScript（`.js`、`.mjs`、`.ts` 等） | 正则字面量中可以出现 `//` 与 `/*`，不做完整语法分析就无法区分正则与除号 |
| Python、Shell、YAML | 字符串块、heredoc、块标量中行首的 `#` 是数据 |
| Markdown | 本仓库的 skill 文本就是 Markdown，修改文字就是修改行为 |
| 其他类型 | 没有逐一核实注释语法，按代码处理 |

这些类型的注释修改仍按 ADR-0002 处理：登记豁免或重跑验证。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| agent 自述「只改注释」后登记豁免 | 无需脚本 | 结论无法复核，与 ADR-0002 否决模型自述的理由相同 | 否决 |
| 按切片裁剪指纹 | 过期误报少 | ADR-0002 已否决：漏掉间接依赖 | 否决 |
| 引入各语言的完整解析器 | 判定更精确 | 校验脚本只依赖 Node.js 与 git，不引入依赖 | 否决 |
| 自写词法扫描，有歧义时按代码处理（本决策） | 无依赖、可复算、误判方向安全 | 只支持五类文件；部分合法写法被保守地按代码处理 | 采用 |

## 后果

**正面**

- 只改注释的修改不再让证据过期，也不触发新一轮评审。
- 判定由脚本完成，结论可以复算。

**代价**

- 新增语言支持时，要先确认该语言的注释与字面量规则，再加入脚本与本 ADR。
- 含 Unicode 转义、SQL 方言歧义写法的文件，注释修改仍要登记或重跑。

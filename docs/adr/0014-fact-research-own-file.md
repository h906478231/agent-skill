# ADR-0014: 事实预调研写入单独的 research.md

- 状态：已接受
- 日期：2026-11-20
- 决策者：agent-skills 团队（用户 2026-11-20 在 `/opsx:explore` 中确认）
- 关联变更：`openspec/changes/move-fact-research-to-research-md`
- 取代：ADR-0012 第 5 条（事实预调研写入 `discussion-log.md` 的回流表与表下小节）

## 背景

ADR-0012 第 5 条把事实预调研的结果写入 `discussion-log.md`：回流表一行摘要，表下 `### D<n> 事实预调研：<主题>` 小节，事实编号 `D<n>-F<m>`。选这个位置的原因是不新增产物位置，也不修改门禁脚本的产物允许清单，因为当时另外三个变更都在修改这个脚本。

`add-fact-research` 归档后，这个位置有三个问题：

1. `openspec-discussion-sync` 为事实预调研写了三条例外规则：「建议落点」只允许两种写法；防丢自检第 2 条把「带入 explore 讨论」视为已有归宿；不写入「未采纳记录」，否则 propose 会把要讨论的问题当作已否掉的方案。
2. grill 的回流与事实预调研共用 `D<n>` 轮次序列，编号交错，与内容无关。
3. `openspec-discussion-sync` 第四节要求每个新子 agent 附带 `discussion-log.md` 的已有内容。事实预调研的「依据」中有 `file:line` 与命令输出，内容长。

事实是讨论的输入，`discussion-log.md` 记录讨论与决策，两种内容的读取方不同。2026-11-20 核对时，修改门禁脚本的活跃变更只剩一个，允许清单外的文件只报 warning，不阻断。

## 决策

1. 事实预调研的结果写入变更根目录的 `research.md`，不写 `discussion-log.md`。
2. 每轮一个小节 `## F<n> <主题>（YYYY-MM-DD）`，事实编号 `F<n>-<m>`，取代行写「取代 F<k>-<m>：<原因与新依据>」。轮次序列只属于 `research.md`。子 agent 的临时编号改为 `T<m>`，避免与轮次编号 `F<n>` 混淆。
3. 小节内保留五段与原来的写法限定。「只增加，不修改」、子 agent 返回后重新读取、局部插入三条规则不变。
4. `openspec-discussion-sync` 删除「事实预调研小节」条目类型与三条例外；「适用范围」写明事实预调研写 `research.md`；第四节要求后续子 agent 同时附带 `research.md` 中没有被取代的事实与弃案。
5. explore、propose 与 ff 的本仓自加区改为读取 `research.md`。门禁脚本的产物允许清单增加 `research.md`，只匹配变更根目录。

ADR-0012 的其他各条不变：事实预调研由只读子 agent 执行，explore 留在主会话，不写 `discussion-log.md`，只写事实，不推荐方案。

## 备选方案

| 方案 | 结论 |
|---|---|
| 保持现状，只在契约中写清楚按标题前缀读取 | 否决：三条例外、共用编号与 prompt 变长三个问题都还在 |
| `research.md` 另定只含事实的格式 | 否决：要另定一套回流规则，子 agent 返回后要转换段名；ADR-0012 否决这条路的理由仍成立 |
| 项目级目录 `openspec/research/`，不绑定变更 | 否决：代码事实跨变更过时更快，没有人负责清理；当前没有多个变更共用事实的记录 |
| 轮次编号用 `R<n>` | 否决：`R<n>` 已是评审轮次 |

## 后果

- 已归档变更中的 `### D<n> 事实预调研` 小节不迁移，读取方不兼容旧格式。2026-11-20 核对时活跃变更中没有这类小节。
- `discussion-log.md` 中不再有事实预调研的回流行。要知道是否运行过事实预调研，看变更目录中有没有 `research.md`。
- 调研后不立项时，变更目录中只剩 `research.md`，由用户删除。
- 已安装的 skill 副本要手动同步后才按新位置写入。

# apply 前置门禁校验（唯一事实源）

> 进入代码实现前必须执行的人工签字校验。`skills/openspec-apply-change/SKILL.md` 与 `claude/commands/opsx/apply.md` 两条调用路径都引用本文件，不各写一份。
> 路径：`<SKILL_DIR>/shared/apply-gate-check.md`

## 何时执行

**仅当项目启用了技术评审门禁时**才执行本校验 —— 判据：**存在 `openspec/changes/<name>/review-summary.md`**。

**无 `review-summary.md` → 直接放行，跳过本校验** —— 该变更未启用门禁，无需审批即可实现。

**L0 豁免的变更不创建 `review-summary.md`**，因此天然走上面的「直接放行」分支 —— 这是设计意图，不是漏检（L0 落点见 `gate-levels.md`）。MVP 且未命中升级信号的变更同理。

是否该走门禁由 `gate-levels.md` 分级决定：提醒放在 `/opsx:propose`、`/opsx:ff` 的收尾输出；判定为豁免时，这两个命令同时在 `overview.md` 开头写入分级行（`gate-levels.md`「分级决策责任」）。本节口径与 `hooks/check-review-approval.sh` 的放行分支一致，改动时两处同步。

## 校验动作（仅在 review-summary.md 存在时执行）

```bash
grep -n -E 'Gate-Verdict(:|：)' "openspec/changes/<name>/review-summary.md"
grep -n 'Technical Review Approved:' "openspec/changes/<name>/review-summary.md"
```

两条命令列出全部匹配行，不直接把输出的第一行当作签字或裁决。只认行首键名：键名之前只能有列表标记（`-`、`*`）、引用标记（`>`）与空白；排除句中、反引号、表格单元格或其他文字后的提及。裁决行与签字行各取最后一行键名行，标记与取值规则见 `gate-policy.md`「机器可读裁决行」，与 hook 相同。

签字标记按原文字面匹配，只认半角冒号。行首不用 grep 的 `[[:space:]]` 判断：它是否包含全角空格、U+00A0 等非 ASCII 空白随 locale 变化；空白按 JS `\s` 的清单识别。

| 情况 | 处理 |
|------|------|
| **`Gate-Verdict: BLOCKED`** | 即使有签字也**停止**，按 `gate-policy.md` 第 6 节判断下一步处理方式 |
| **签字行仍是空白占位**（空或只有空白，含全角空格等非 ASCII 空白、`____`、`<签名>`、以下划线开头再补括号说明如 `__________ （签字 / 日期）`） | 门禁跑过但无人批准。**停止**，请用户审阅 `review/*.md` 后签字（判定规则与 `hooks/check-review-approval.sh` 一致） |
| **缺 `Gate-Verdict` 行**（本格式引入前生成的旧版产物） | 从门禁裁决项读裁决：`BLOCKED` 或读不出裁决时**停止**并请用户确认；`READY_FOR_HUMAN_APPROVAL` 再按签字行判断 |
| **已签字且 `Gate-Verdict: READY_FOR_HUMAN_APPROVAL`** | 签字校验通过，继续比较规划输入版本 |

L3 的 `复核:` 行是建议项，留空不影响放行。

## 比较规划输入版本（签字校验通过后）

按 `gate-policy.md` 第 5 节识别登记行并计算任务内容 SHA-256。步骤按顺序执行：

1. 只读取本轮「评审输入版本」。如果它不是逐个文件的 SHA-256，停止并提示重走门禁。文件项须有相对路径和 64 位十六进制原始值；不可把旧轮次的值或当前值当成评审记录。
2. 比较集合取本轮汇总列出的文件与当前存在的 `proposal.md`、`design.md`、`tasks.md` 和 `specs/` 下全部文件的并集。只在一边出现的文件按已改变处理。
3. 读取序号大于登记基线序号的登记行，包含记录输入后同轮写入的行。基线序号无效、登记序号无效或非零基线序号没有对应行时停止。旧汇总无基线时，只认能确定在评审输入之后的登记，不能确认的同轮行不算已登记。有方案变更行时停止，按 `gate-policy.md` 第 3 节提示重走受影响维度。不因文件哈希相同而跳过这一步。
4. 比较文件原始 SHA-256。两边均有 `tasks.md` 且原始值不同时，再按第 5 节比较任务内容 SHA-256。只因进度记录而异时按未改变处理；旧汇总没有任务内容 SHA-256 时只比较原始 SHA-256。补充值无效也不视为相同。集合内文件均未改变时放行，不要求登记或确认进度记录。
5. 存在实质差异时，按第 5 节核对当前文件集合、逐文件哈希、登记最后序号与已核对版本一致。`tasks.md` 仍按上一步排除规定的进度记录。缺少记录、有未经核对的登记或不一致时停止，提示先走 `/opsx:update` 或重走门禁。不能凭文件名命中放行；旧汇总缺少已核对版本时，有实质差异就停止。
6. 核对通过后，输出第 3 步选出的登记行，用 `AskUserQuestion` 请用户确认这些行的规划档位。未确认就停止，提示重走受影响维度。确认后还要复核，不能直接写入。

### 确认返回后的复核

提问前，在当前会话记录当次核对的文件集合、逐文件原始 SHA-256、任务内容 SHA-256、登记最后序号及显示的登记行完整内容。同时保留本轮评审输入版本、登记基线序号、签字和裁决。不写持久文件，不用提问后的值反推。

确认返回后，在开始实施、首次写入前重新读取并核对上述各值，包括最后的裁决行和签字行。仅允许第 5 节定义的任务进度记录变化。正文、文件集合、登记内容（即使序号相同）、轮次与版本记录、签字或裁决变化，或无法核对时，停止，不沿用确认，不修改签字行。核对通过才放行。

## 禁止事项

- 禁止代替用户签字
- 禁止修改签字行
- 禁止劝说用户跳过本步骤

Bash 侧的 `PreToolUse` hook 只拦得住 `openspec apply` 命令，**看不到 `/opsx:apply` 斜杠命令与 skill 调用这条路径** —— 本校验是该路径上唯一的检查点，不得跳过。

## 放行后必须做的事

把 `review-summary.md` 中「有条件通过」的条件带入实现：**每条条件对应 `tasks.md` 的一个任务项，条件满足后才可勾选该任务。** 条件不落地，门禁等于白跑。

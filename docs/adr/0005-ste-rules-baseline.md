# ADR-0005: STE 规则以 ASD-STE100 为基线，中文改写并以 CONTEXT.md 扩展技术词汇

- 状态：已接受
- 日期：2026-10-06
- 决策者：agent-skills 团队
- 关联变更：STE 门禁 `add-ste-gate`（待创建）

## 背景

AI 产出的方案与对话回复存在一词多义、表述模糊的问题，开发者容易误读。ASD-STE100 是成熟的受控写作标准，但有两个约束：

1. 规则与词典都面向英文，而本仓库要求输出中文。
2. ASD-STE100 Issue 9（2025-01）可免费获取，但除列明的几类组织外，复制或发布需 ASD 书面授权；本仓库为 Apache-2.0，不能分发官方约 900 词的受控词典。

STE 本身把词汇分为两层：官方受控通用词，以及由项目定义的技术名词（R1.5）与技术动词（R1.12）。

## 决策

**STE 规则以 ASD-STE100 为骨架，分三层落地：**

1. **写作规则**：逐条改写为中文，保留原规则编号以便追溯（如 `C-R4.1 ← STE R4.1`）；只引用编号、自行复述，不复制原文。英文专属规则（冠词、-ing、撇号等）不采纳。
2. **通用受控词表**：按 STE 原则（一词一义、单一词性、非受控词给出受控替代）自行编写中文词表，随 skill 内置，项目可在 `openspec/ste.yaml` 增删；不翻译、不摘抄官方词条。
3. **技术词汇**：CONTEXT.md 作为 STE 技术名词与技术动词扩展，术语可标注 `技术名词` / `技术动词` 类别；`_Avoid_` 为禁用别名（见 ADR-0003）。

**分级原则**：可精确匹配的规则（禁用别名、非受控通用词、模糊词）在产物中阻断；启发式与统计类规则（名词串、被动语态、句长、程序步骤、安全提示）只告警。

## 备选方案

| 方案 | 否决理由 |
|------|---------|
| 改用英文 STE 写作 | 违反中文输出要求，团队阅读成本上升 |
| 中英混写 | 同一概念出现中英两种写法，违背一词一义 |
| 只用 CONTEXT.md，不引入 STE | 丢失 STE 的写作规则与通用词约束，只解决项目术语一层 |
| 复制官方词典进仓库 | 违反 ASD-STE100 版权条款 |

## 后果

- 中文句长阈值（描述句 40 字、指令句 30 字）由 STE 25 词 / 20 词按约 1.5 字/词折算，折算比为经验值，因此只告警。
- 编写中文规则表时需对照官方 Issue 9 原文核对规则编号。

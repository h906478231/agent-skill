# ADR-0015：不改变已评审行为的规划修改不使签字失效

- 状态：已接受
- 日期：2026-11-24
- 变更：`add-technical-review-convergence`

## 背景

写入评审条件、修订措辞或移出需求，都会改变规划文件。只按文件版本判断时，这些变化与新增技术方案一样会触发重评。apply 自己写入的基线任务数与任务勾选状态也会改变 `tasks.md`，使中断后的续跑误判为规划已改。

## 决策

按 [门禁规则第 5 节](../../skills/openspec-technical-review/shared/gate-policy.md#5-定稿与签字后修改) 登记规划修改。措辞、条件落点、范围收窄不使签字失效；方案变更重走受影响维度并重新签字。apply 核对已登记的差异并请用户确认，verify 核对登记的规划档位。正常任务进度不写入登记表。

保留逐文件原始 SHA-256，并为 `tasks.md` 另记任务内容 SHA-256。两个值服务不同目的：原始值记录评审输入；任务内容值让 apply 区分正常任务进度与任务内容修改。没有任务内容值的旧汇总仍用原始值比较。

## 理由与取舍

保留签字的三档不引入未评审的行为。重新评审这些修改会增加轮次，却不能替代对具体差异的核对。保留人工确认和 verify，可以发现条件超出原文或移出的内容仍有引用等情况。

备选方案是每次修改都要求重评，或保存规划快照并由门禁脚本分类。前者会重新拦截正常续跑；后者新增存储和维护成本。本次只修改规则与提示词，不改变签字行、hook 或门禁脚本。

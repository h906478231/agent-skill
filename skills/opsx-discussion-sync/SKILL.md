# 子 agent 讨论回流（Discussion Sync）

## 解决什么问题

技术评审门禁的子 agent 有明确落盘约定（写 `review/<role>.md`），所以结论跑不掉。但探索、建模、方案对比类的子 agent **只返回自由文本** —— 主 agent 在对话里复述一遍，这一轮就散了。后果有三个：

1. 子 agent 给的「建议改 design 第 3 节」没人执行，也没人记它被否了；
2. 未决问题散在多轮对话里，用户被反复打断，或者干脆没人问；
3. 下一轮全新上下文的子 agent 重复探索同一条已经否掉的死路。

本 skill 用**契约 + 落盘 + 自检**三件事堵住这三个洞。

## 一、子 agent 的 handoff 契约

**所有被主 agent 调起的子 agent，返回内容的最后必须是这五段，段名固定、一段不能少。** 该段无内容就写「无」，不允许省略段落 —— 省略和「确实没有」必须能区分开。

```markdown
## 结论
<一句话。是什么结论，不是「我做了什么」。>

## 依据
<读了哪些文件得出的，带 file:line。没有依据的结论要标「推断，未验证」。>

## 建议落点
<改哪个 artifact 的哪一节，改成什么。一条一行。没有就写「无」。>

## 未决问题
<需要人决定的点。每条给候选选项与各自代价，不要只抛问题。没有就写「无」。>

## 弃案
<考虑过但否掉的方案 + 否掉的具体理由。没有就写「无」。>
```

三段的写法要求：

- **依据**必须能被复核。「根据经验」「一般来说」不算依据 —— 这类结论一律标「推断，未验证」，让主 agent 知道它的可信度。
- **建议落点**要能直接执行。「建议优化性能」不是落点，「design.md 第 4 节的批大小从 100 改为 500，理由 X」才是。
- **弃案**是给下一轮子 agent 看的。全新上下文的子 agent 没有本轮记忆，不写弃案它就会把同一条死路再走一遍 —— 与门禁「评审意见闭环记录」同一个思路。

主 agent 在启动子 agent 时，必须把这个五段格式写进 prompt。

## 二、主 agent 的回流动作

收到子 agent 返回后，**必须做完以下三件事再继续**，只在对话里复述一遍不算数。

### 1. 追加 discussion-log.md

追加一行到 `openspec/changes/<name>/discussion-log.md`（文件不存在则创建）：

| 轮次 | 日期 | 子agent | 结论 | 未决 | 已落到哪个 artifact |
|------|------|---------|------|------|-------------------|

- 轮次从 `D1` 开始递增，与门禁的 `R1/R2` 分开编号。
- 「已落到哪个 artifact」写具体文件与章节；若未采纳，写 `未采纳（理由见下）` 并在表下方「未采纳记录」小节写明理由。

### 2. 逐条处理建议落点

每一条「建议落点」只有两个合法归宿，**没有第三种**：

| 归宿 | 动作 |
|------|------|
| 采纳 | 改目标 artifact（`proposal.md` / `design.md` / `specs/*/spec.md` / `tasks.md`），并在 log 里写明落到哪 |
| 不采纳 | 在 `discussion-log.md` 的「未采纳记录」写 `落点 | 不采纳理由 | 决策人` |

「先记着以后再说」不是归宿 —— 那等于丢了。真要延后，就在 `tasks.md` 建一条任务或记进「未决问题」。

### 3. 未决问题批量确认

把本轮**所有**子 agent 的未决问题**汇总后一次性**用 **AskUserQuestion** 问用户，不要每收到一个子 agent 就打断一次。用户答复后，答案要回写到对应 artifact，并在 `discussion-log.md` 标记该未决项已关闭。

## 三、防丢自检

**主 agent 结束本轮回复之前，必须逐条确认：**

- [ ] 本轮每个子 agent 的返回都包含完整五段？缺段的要追问补齐，不能自己脑补。
- [ ] 每条「建议落点」都有归宿（已落盘 / 已记未采纳）？
- [ ] 每条「未决问题」都已问用户或已记入 `discussion-log.md`？
- [ ] `discussion-log.md` 已追加本轮记录？

**有任何一条没做完，不得结束本轮。** 这是本 skill 唯一的强制点 —— 前面两节都靠它兜底。

## 四、下一轮上下文注入

启动**任何**新子 agent 时，prompt 中必须附带 `discussion-log.md` 的既有内容（至少包含「结论」列与「未采纳记录」「弃案」）。

理由与门禁给子 agent 附「评审意见闭环记录」完全一致：子 agent 是全新上下文，不给历史，它必然重复劳动或推翻已定结论。

## 产物的 git 归属

`discussion-log.md` 与门禁产物同策略：提交 git，随 `openspec archive` 整体进 `changes/archive/<name>/`，不进 `specs/`。

理由：它是「为什么当初这么定 / 为什么否掉那个方案」的唯一记录。删掉之后，半年后接手的人只能看到结论，看不到弃案 —— 于是把弃案再实现一遍。

## 适用范围

- **适用**：探索、领域建模、方案对比、调研类子 agent —— 即返回自由文本、没有既定落盘约定的场景。
- **不重复适用**：技术评审门禁的五个角色子 agent 已有 `review/<role>.md` 落盘约定与闭环记录机制，走那套即可，不必再写一份 `discussion-log.md`。
- 相关：`claude/agents/ddd-architect-claude.md` 作为建模主控 agent，调度建模子 agent 时按本 skill 执行。

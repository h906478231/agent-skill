# ADR-0011: 托管期间的用户决策只经飞书卡片进入，对外写入由调度脚本在决策后执行

- 状态：已接受
- 日期：2026-11-16
- 决策者：agent-skills 团队（用户 2026-11-06 至 2026-11-16 在 `add-autopilot-loop` 的五轮技术评审中确认）
- 关联变更：`openspec/changes/add-autopilot-loop`（design D14）
- 编号说明：ADR-0009 已用于「quality 询问 finding 处理方式」，ADR-0010 已用于「仅测试档位」

## 背景

签字之后，用户在每个阶段结束时输入下一条命令，而进度视图已能算出下一条命令。agent 的提问只能在终端中回答，用户离开电脑时流程停住。2026-11-03 的两个实验证明：`claude -p` 能停在 `AskUserQuestion` 处、之后恢复会话，飞书卡片回调能把用户的点选带回本机。2026-11-06 的实验 3 证明：Claude Code 合并各设置来源的允许规则，`--allowedTools` 不能收窄它们，local 来源的规则会让 headless 运行跳过权限宿主。

## 决策

1. 托管期间，用户的决策只经飞书卡片回调进入：桥接脚本核对操作人是配置中的本人、事件没有处理过、卡片对应一个等待回复的托管决策，核对通过才写入回复。
2. 对外写入（提交与合并、推送）只在用户点选出口卡片后由调度脚本执行，并回读结果。headless 运行的 agent 不能执行 `git commit`、`git merge`、`git push`、`flows-cli` 与 `lark-cli`。
3. 签字仍由用户在会话中手写。托管只接受进度规则为 R6–R11 的变更，不运行 explore、grill、propose、review、update。
4. 托管只加载 user 与 project 设置来源，每次启动或恢复 claude 之前核对其中的允许规则、额外工作目录与 hook，以及 skill、命令与 subagent 文件头中的授权；有清单外的条目时不启动，发通知卡片。

## 备选方案

| 方案 | 结论 |
|---|---|
| 扩展现有云舟 workflow | 否决：恢复依赖同一会话，隔天的决策要重跑整个 workflow；路由与门禁核对靠 LLM 判断 |
| 常驻编排服务（Agent SDK） | 否决：要服务器、数据库与长期凭据，没有证据说明瓶颈在并发或多人 |
| 按分级自动通过确认类决策 | 否决：本变更不自动通过任何决策；积累托管决策文件后再评估 |
| 加载全部设置来源，只靠权限宿主拦截 | 否决：实验 3 证明 local 来源的允许规则会绕过权限宿主 |

## 后果

- 状态只在变更目录的 `decisions/` 与本机托管目录中，用户随时可以查看或撤回。
- 托管使用已安装的 skill 副本；副本落后于仓库时运行的是旧规则，发布前要同步副本。
- 例外（风险 R17）：运行前后核对发现处理记录或签署字段与用户回复对不上时，发会话告警而不是直接作废托管。用户选「补充说明后继续」后，agent 写入的签署字段可能保留在文件中；告警决策文件保存不一致的各项与用户的选择，可以事后追溯，但不能防止误点。

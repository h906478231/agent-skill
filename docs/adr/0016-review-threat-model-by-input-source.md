# ADR-0016: 技术评审按输入来源确定威胁模型，约束流程内 agent 的检查不防有意伪造

- 状态：已接受
- 日期：2026-11-22
- 决策者：用户 2026-11-22 在 `/opsx:grill` 中确认
- 编号说明：ADR-0015 已由 `add-technical-review-convergence` 的任务 3.4 预定

## 背景

工作流没有写下评审的威胁模型。`fix-autopilot-minor-findings` 把流程内 agent 当作攻击者评审运行前后核对，安全 finding 编号到 SEC-41，其中一部分要求先查明检查做法再专门构造输入（如 SEC-24 用大小写不同的路径躲开 hook）。`add-technical-review-convergence` 写明 agent「配合流程但会出错」，同类门禁只报出 5 条。两次的差别来自前提，不来自方案质量。

## 决策

1. 评审约束流程内 agent 的检查（门禁、hook、签字读取、运行前后核对）时，假设 agent 会出错、会走捷径，不会有意伪造。出错与走捷径的触发场景必须报出，有意伪造的触发场景默认不报。
2. 外部输入与对外发送的内容按攻击者评审。把外部文本交给流程内 agent 的入口算外部输入。
3. 变更需要防有意伪造时（如签字人与作者不是同一个人），在 design 中声明，按对抗模型评审。

术语见 `CONTEXT.md`：流程内 agent、外部输入、走捷径、有意伪造。

## 理由

能有意伪造的 agent 可以不经 apply 直接修改代码，`gate-policy.md` 已写明门禁是流程纪律工具，不是安全边界。为它加固解析器不提高门槛，只让评审无法收敛。走捷径有固定方向（让门禁放行），只按「出错」评审会漏掉 SEC-01、SEC-18 这类问题，所以单独列为必须拦住的一档。

## Considered Options

- 始终把流程内 agent 当作攻击者：绕过写法列不完，评审不收敛。
- 只防出错：漏掉走捷径。
- 不设默认值，由每个变更自定：同类门禁的评审结论不可比较。

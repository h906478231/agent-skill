# ADR-0002: 切片证据与双轴评审基线统一采用 git tree 实现指纹

- 状态：已接受
- 日期：2026-09-30
- 决策者：agent-skills 团队
- 关联变更：`openspec/changes/add-dual-axis-review-evidence`

## 背景

切片新鲜证据与双轴评审基线都需要一个「当前实现版本」的标识，用来判断验证结论是否仍对应当前代码。候选有两个：

1. 复用云舟 workflow 路由阶段已有的 `fingerprint`；
2. 由校验脚本从工作区内容确定性计算一个仓库级指纹。

路由阶段的 `fingerprint` 由模型汇报，含义是「决策与产物状态」，只用于检测编排循环是否空转，**不是代码内容的函数**：同一份代码可能得到不同值，改了代码也可能不变。用它判定证据新鲜度，等于把新鲜度交给模型自述。

## 决策

**1. 指纹由 `skills/openspec-technical-review/scripts/implementation-gate.mjs` 确定性计算，记为 `git-tree:<sha>`**

在临时 index 中以 HEAD 为种子写入工作区全部改动（含未跟踪文件，遵守 `.gitignore`），移除规划目录（通常为 `openspec/`）后取 `git write-tree` 的哈希。

- 排除规划目录：写证据、勾选 `tasks.md`、写评审报告不会让指纹变化。
- 内容寻址：提交与否不影响指纹，只有实现内容变化才会变。
- 对象写入对象库：两个指纹之间可用 `git diff-tree` 求出变化文件，用于列出过期原因与核实豁免记录。
- 不改用户 index、不提交；唯一副作用是不可达对象，由 git gc 按默认策略回收。

**2. 指纹是全仓口径，不按切片裁剪**

任何实现文件变化都会让所有切片证据的指纹失配。是否真的影响某个切片，由 Verify 依据变化文件判断：影响则重跑；确认无关则按豁免格式登记（脚本核对「变化文件」是否列全）；无法判断按过期处理。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 复用路由 `fingerprint` | 无新增计算 | 模型自述、非代码内容函数，无法证明证据对应当前代码 | 否决 |
| 按切片变更文件计算局部指纹 | 过期误报少 | 漏掉切片间接依赖的文件变化，给出「新鲜」的错误结论 | 否决 |
| 全仓 git tree 指纹 + 豁免链（本决策） | 确定、可复算、可求差异 | 后续切片会让先完成切片的证据失配，需重跑或登记豁免 | 采用 |

## 后果

**正面**

- 证据与评审基线共享同一口径，Verify / Archive 可以机械判定新鲜度，不依赖模型判断。
- 证据的 `Fingerprint Source` 与 `git-tree:` 前缀标明算法，将来换算法时新旧证据可区分。

**代价**

- 多切片变更在全部完成后需刷新各切片证据（apply 规则已要求在跑完整测试套件时同步刷新）。
- 需要 git 与 Node.js ≥ 16；超大仓库计算指纹要读取全部工作区文件，耗时随仓库体积增长。
- 指纹对象被 git gc 回收后，旧豁免记录无法再核实，按过期处理（重跑一次即可恢复）。

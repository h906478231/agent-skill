# CONTEXT.md（领域术语表）格式与更新规则

> 本文件是 CONTEXT.md 格式的唯一事实源。CONTEXT.md 是项目级资产：跨变更复用、提交 git、不随 `openspec archive` 归档。

## 结构

```markdown
# {领域/上下文名称}

{一两句话：这个领域是什么、为什么存在。}

## Language

**Order（订单）**:
用户发起的一次购买请求，含一个或多个订单项，有独立生命周期（创建→支付→履约→完成）。
_Avoid_: 单子、购买记录、交易

**Cancellation（取消）**:
整单取消：订单内全部订单项一并回退。不支持部分取消。
_Avoid_: 退单、撤单

**Customer（客户）**:
下单的自然人或组织。
_Avoid_: 客户端、买家、账号
```

## 规则

- **要有主见**：同一概念存在多个说法时，选最好的一个，其余列入 `_Avoid_`。_Avoid_ 不是禁词表，是「新代码和新文档不要再用」的约定
- **定义要收紧**：最多一两句。定义它**是什么**，不写它做什么、怎么实现
- **只收本领域特有的术语**：通用编程概念（超时、重试、工具类模式）不入表——入表前先问「这是本领域独有的概念，还是通用概念？」只有前者入表
- **术语自然成簇时用子标题分组**；单一领域平铺即可

## 更新时机（访谈中随手做，不攒批）

| 触发 | 动作 |
|------|------|
| 新术语被敲定 | 立即写入；文件不存在则此刻创建（懒创建） |
| 用户用词与既有术语冲突 | 立即指出（「术语表里 Cancellation 是整单取消，你现在说的像是部分取消——哪个对？」），澄清后立即更新 |
| 模糊/ overloaded 词被精确化 | 更新为精确术语，旧词进 `_Avoid_` |
| 用户陈述与代码行为矛盾 | 对照代码求证，澄清后更新 |

## 与 OpenSpec artifact 的对接

- `CONTEXT.md` 存在时：proposal / design / specs / tasks 与**代码命名**必须使用统一语言，不自造同义词
- delta spec 的 `#### Scenario:` 描述、tasks.md 的切片标题，用术语表里的词，少解释一段背景
- CLAUDE.md / AGENTS.md 应包含一行指向本文件的约定（本仓已加）

## 单领域 vs 多领域仓库

- **单领域（多数仓库）**：根目录一个 `CONTEXT.md`
- **多领域**：根目录 `CONTEXT-MAP.md` 列出各领域 CONTEXT.md 的位置与关系（谁给谁发事件、共享哪些类型）；访谈时按当前主题定位到对应领域文件更新
- 判定：有 `CONTEXT-MAP.md` → 多领域；只有根 `CONTEXT.md` → 单领域；都没有 → 第一个术语敲定时在根懒创建

### 2️⃣ P0-2: 分级自动判定工具

**文件**：
- [`scripts/classify-change.js`](../scripts/classify-change.js) - 核心逻辑
- [`scripts/classify-change.sh`](../scripts/classify-change.sh) - Shell 包装器
- [`docs/classify-change-guide.md`](../docs/classify-change-guide.md) - 使用指南

**功能展示**：
```bash
$ node scripts/classify-change.js add-user-nickname

┌─────────────────────────────────────────────────────────┐
│  变更：add-user-nickname                                 │
├─────────────────────────────────────────────────────────┤
│  变更类型：L1                                            │
├─────────────────────────────────────────────────────────┤
│  判定依据：                                              │
│    ✓ L1: 新增字段, 单表CRUD                              │
│    ○ L2: 批量操作                                        │
├─────────────────────────────────────────────────────────┤
│  建议跑的维度：                                          │
│    database + security                                  │
│                                                         │
│  预计耗时：2-4 分钟                                      │
└─────────────────────────────────────────────────────────┘
```

**判定规则**：
- L0 触发：纯文案、注释、配置、格式化
- L3 触发：MQ/异步、批量≥1万、表结构、对外接口、租户隔离
- L2 触发：跨模块、缓存、新增业务流程
- L1 默认：单表 CRUD、新增字段

**集成点**：
- `skills/opsx-technical-review/SKILL.md` 前置校验（Step 4）
- 在 `/opsx:review` 启动前自动运行

### 3️⃣ P1-5: AI 误报自动检测与降级

**文件**：[`skills/opsx-technical-review/shared/false-positive-detection.md`](../skills/opsx-technical-review/shared/false-positive-detection.md)

**检测规则**：

| 规则 | 触发条件 | 处理 |
|------|---------|------|
| 1. 触发场景模糊 | 包含"可能/有时/偶尔" | 自动降级（Blocker→Major→Minor） |
| 2. 跨维度矛盾 | Security 说"外部输入"，Architecture 说"内部接口" | 提示人工复核 |
| 3. 量级不匹配 | Performance 报问题，但数据量 < 1000 | 提示可能过度 |
| 4. 已有类似实现 | 建议"引入重试"，但代码库已有 | 提示复用 |
| 5. 过度设计 | 建议"引入 MQ"，但 QPS < 10 | 提示简化 |

**输出示例**：
```markdown
## 疑似误报检测

| finding ID | 原级别 | 建议 | 检测理由 |
|-----------|-------|------|---------|
| PERF-02 | Blocker | 降级为 Major | 当前数据量 500 条，性能影响可能很小 |
| SEC-03 | Blocker | 需人工复核 | Architecture 维度标记为内部接口，与本 finding 矛盾 |
```

**集成点**：
- `skills/opsx-technical-review/SKILL.md` 汇总步骤（Step 2）

## 🎓 经验总结

### ✅ 做得好的地方

1. **优先解决核心痛点**
   - 识别出"新人入门门槛"是阻碍推广的最大障碍
   - 先做 P0-1 和 P0-2，而非追求完美的技术方案

2. **渐进式改进**
   - 不是一次性重构整个工作流
   - 而是增量添加工具，保持向后兼容

3. **实用主义**
   - 分级工具基于简单的关键词匹配（而非复杂的 NLP）
   - 误报检测基于规则（而非机器学习模型）
   - MVP 先行，根据实际反馈再迭代

4. **文档驱动**
   - 每个工具都配完整的使用指南
   - 测试用例和示例齐全
   - 新人能自助上手

### ⚠️ 需要注意的风险

1. **分级工具的局限性**
   - 基于关键词，可能误判
   - 边界情况（如"注释掉旧的 MQ 代码"）需人工判断
   - 需要持续收集数据优化规则

2. **误报检测的覆盖率**
   - 当前只有 5 条规则
   - 可能漏掉其他类型的误报
   - 需要根据实际案例补充

3. **工具的维护成本**
   - 随着项目技术栈变化，规则需要调整
   - 需要定期回顾和优化
